# Прогноз мощности турбин: автономный CSV-only эксперимент

Это самостоятельный офлайн-эксперимент по прогнозу нормированной мощности двух ветротурбин на 48 часов вперёд. Он использует только предоставленные исторические CSV с наблюдениями и прошлые значения признаков. Внешняя погода, GFS, сетевые запросы и погодные кэши не являются входом итоговой модели.

Пакет **не является интеграцией с backend** и не реализует контракт погодного приложения `docs/CONTRACT.md` версии 0.5. В частности, он выдаёт только точечный прогноз, а не интервалы P10/P90 и не API-ответ этого контракта.

## Что включено

- вектор из 48 прямых выходов на каждый момент выдачи;
- только причинные lag/rolling-признаки и календарь, без будущих наблюдений;
- 14 заранее заданных кандидатов: persistence, seasonal median, Ridge, Extra Trees, Random Forest и CatBoost;
- временная настройка и замороженный holdout;
- итоговый артефакт и отдельный лучший обучаемый артефакт с SHA-256 манифестами.

Результат уже выполненного эксперимента: `best_model.pkl` — **persistence**, общий победитель по объявленной валидации. `best_ml_model.pkl` — **CatBoost**, лучший только среди обучаемых кандидатов. CatBoost не заменяет базовый победивший вариант после просмотра holdout. Точные метрики, покрытие и ограничения приведены в [docs/results.md](docs/results.md).

## Быстрый запуск после клонирования

Запускайте команды из каталога `ml-prognoz-model`.

```bash
uv sync --extra dev
uv run wind-forecast --config configs/history.json prepare
uv run wind-forecast --config configs/history.json build-dataset
uv run wind-forecast --config configs/history.json plan
uv run wind-forecast --config configs/history.json train
uv run wind-forecast --config configs/history.json predict \
  --model artifacts/csv_only/best_model.pkl \
  --origin 2026-01-31T19:00:00Z --hours 24
```

Конфигурация ожидает исходные файлы в `../data/raw/turbine_1.csv` и `../data/raw/turbine_2.csv` относительно корня этого пакета. Это те же файлы, что использовались в исходном запуске, с идентичными SHA-256. После клонирования сначала необходимы `prepare`, затем `build-dataset`: подготовленные Parquet, архивы и wheel в репозиторий не включены.

`run` выполняет `prepare`, `build-dataset` и `train` последовательно. Обучение воспроизводимо при тех же CSV и окружении, но занимает заметно больше времени, чем команды подготовки и планирования.

## Практические границы

CSV заканчиваются январём 2026 года. Поэтому полный ежедневный replay февраля и оценка точности на всём феврале невозможны без новых фактических измерений: для очередного прогноза нужны последние 24 полных часа наблюдений, а для проверки — будущие фактические метки. Часовой пояс источника не документирован; в эксперименте временно принят фиксированный UTC+05:00 (`Etc/GMT-5`).

Пакет содержит исходный код, документацию, отчёты и финальные артефакты. Исходные CSV уже находятся в корневом `data/raw/` репозитория и не дублируются этим изменением. Подготовленные таблицы, ZIP-архив и wheel не коммитятся. Подробнее: [docs/README.md](docs/README.md).
