# Воспроизводимость и происхождение результата

Активный сценарий полностью офлайн после размещения исходных CSV. Используются `configs/history.json` и команда `wind-forecast` из `src/wind_forecast/offline.py`. Пакет является самостоятельным экспериментом, а не частью backend и не реализацией погодного API-контракта v0.5. Он не использует внешнюю погоду и выдаёт точечные значения, не P10/P90.

## Исходные файлы и размещение после клонирования

Из корня `ml-prognoz-model` конфигурация ожидает:

```text
../data/raw/turbine_1.csv
../data/raw/turbine_2.csv
```

Это исходные CSV из выполненного эксперимента; их SHA-256 должны совпадать с зафиксированными в манифестах запуска. CSV уже закоммичены в корневом `data/raw/` репозитория и этим пакетом не дублируются. Подготовленные Parquet, ZIP-архив и wheel не добавляются. В пакет включены исходный код, тесты, документация, отчёты и финальные артефакты.

Пути внутри сохранённых манифестов описывают исходный запуск и могут указывать на прежний каталог. Для повторного запуска используются относительные пути из `configs/history.json`; SHA-256 данных и моделей остаются прежними.

## Повторение конвейера

```bash
uv sync --extra dev
uv run wind-forecast --config configs/history.json prepare
uv run wind-forecast --config configs/history.json build-dataset
uv run wind-forecast --config configs/history.json plan
uv run wind-forecast --config configs/history.json train
uv run pytest
```

После установки зависимостей все эти этапы работают без сети. Если зависимости уже находятся в кэше, `uv sync --offline --extra dev` запрещает и скачивание пакетов. `run` — сокращение для последовательного `prepare`, `build-dataset` и `train`.

После свежего клонирования нельзя начинать с `train`: сначала создайте часовые данные через `prepare`, затем обучающую таблицу через `build-dataset`. Команда `plan` позволяет проверить временные окна до обучения. Для сохранённого артефакта пример инференса:

```bash
uv run wind-forecast --config configs/history.json predict \
  --model artifacts/csv_only/best_model.pkl \
  --origin 2026-01-31T19:00:00Z --hours 24
```

## Что фиксируется

- Хеши исходных CSV и происхождение часовых меток записываются в манифестах.
- Используется временное допущение о фиксированном UTC+05:00 (`Etc/GMT-5`): часовой пояс поставщика не документирован.
- Часовая метка требует шести валидных различных 10-минутных наблюдений; длинные пропуски и целевые значения не импутируются.
- Моменты прогноза идут каждые шесть часов с привязкой к 19:00 UTC; каждый пример содержит прямой вектор из 48 целей и 48-часовой gap на cutoff.
- До обучения зафиксированы 14 history-only кандидатов и хронологическое правило выбора.

Финальный общий выбор — baseline persistence (`best_model.pkl`) по средней валидационной MAE. Отдельный `best_ml_model.pkl` — CatBoost, лучший среди обучаемых кандидатов. Это разные утверждения; лучший CatBoost не был повышен до общего победителя по результатам holdout. Метрики и покрытие находятся в [results.md](results.md).

CSV обрываются в январе 2026 года. Поэтому без новых фактических измерений нельзя ни запускать полный ежедневный прогнозный replay февраля с нужной недавней историей, ни оценить его на полных февральских метках. Старые погодные кэши и pilot-результаты относятся к legacy-экспериментам и исключены из этих утверждений о воспроизводимости.
