# Брейншторм №1 · 23.09, 13:20–13:50 · **черновик, не финальное решение**

Первый разгоночный проход по задаче «Agentic AI для прогнозирования выработки ВЭС».
Решения ниже — рабочие гипотезы; финальный контракт — `docs/CONTRACT.md` после ратификации.

## Выбор задачи
Рассмотрены: Логистика (заказы поставщикам), Торговля (консультант ekt.kz), Инновации (протоколы
совещаний), Энергетика (прогноз ВЭС). Выбрана **Энергетика**: данные выданы, архивные прогнозы погоды
доступны бесплатно (Open-Meteo Previous Runs API, проверено), порога точности нет, отраслевой опыт команды
в промышленной телеметрии. Протоколы совещаний отклонены: ТЗ запрещает облачные API для распознавания речи.

## Как понимаем «Agentic AI»
Цикл из ТЗ: погода → подготовка → модель → почасовой прогноз → анализ → пересчёт при обновлении.
- Числа прогноза считает **ML-модель**, не LLM.
- LLM — управление: порядок инструментов, обработка сбоев источника, решение о пересчёте после
  события «вышел новый прогон погоды», текстовая сводка для диспетчера по JSON-анализу.
- Без ключа — детерминированный режим с теми же порогами; числа совпадают.

## Реализация агента: function calling, не MCP
- Один реестр из 6 инструментов (`fetch_weather`, `check_data`, `run_model`, `analyze_forecast`,
  `recalc_forecast`, `publish_forecast`) → потребители: LLM-цикл, детерминированный режим,
  опционально MCP-сервер.
- MCP в ядре не нужен: лишний процесс и точка отказа при условии «не запустилось — недопуск».
  MCP-адаптер поверх того же реестра — только если к 15:30 ядро работает (история для Demo Day).
- Основа цикла — `docs/references/agent_loop.py`; убрать обязательность `OPENAI_API_KEY` при импорте.

## Пользователи и поток
**Диспетчер ВЭС:** агент сам выпускает прогноз по событию нового прогона → утром готовый выпуск
(версия, время, причина) → график P50 с полосой P10–P90, турбина 1 / 2 / ВЭС → флаги (рампа,
обледенение, расхождение погодных моделей, риск отключения) и сводка → вопрос агенту «почему провал
в 15:00» → CSV для заявки → при новом прогоне агент пересчитывает сам, прошлая версия пунктиром.

**Эксперт-жюри:** `git clone` → `docker compose up` → работает без нашего ключа; или CLI
`windcast.backtest` → 28 CSV → `scripts/verify.py` PASS (включая проверку «без будущего»);
или `https://pushin.codes` с LLM-режимом.

## Экраны
1. **Выпуск:** лента дат, статус версии, график 48 ч с полосой, панель агента, флаги, сводка, CSV,
   кнопка «Имитировать новый прогон» (пересчёт v1 → v2 на глазах).
2. **Февраль целиком:** прогон 28 выпусков, календарь-теплокарта выработки.
3. **Качество:** январь, ошибка модели против персистентности, климатологии и кривой мощности.

Продвинутое (после ядра, до 16:15): «Спросить агента» с вкладами признаков, разброс погодных моделей,
мини-карта турбин со стрелкой ветра, MCP-адаптер.

## Открытые вопросы
- Сдвиг часов SCADA: UTC+5 или UTC+6 — выбрать по бэктесту.
- Один или несколько погодных источников в Previous Runs API.
- Кто берёт агент (T4) и API (T5).
