# Данные за 10 минут

Ни один кейс на этих хакатонах не давал данных в достатке. Без данных демо мёртвое, а «функциональность прототипа» — это 25 баллов.

## Режим A — синтетика (данных нет)

Напиши **один скрипт** `backend/seed.py` (или `.ts`), который создаёт весь набор из сущностей контракта. Требования:

- **Правдоподобие важнее объёма.** 30 живых записей лучше 10 000 пустых. Казахстанские имена, города, объекты, единицы измерения, даты этого месяца.
- **Сценарная дуга**: норма → отклонение → развязка. В данных должен быть заложен тот случай, который агент поймает на демо. Например: три акта с одинаковой причиной на двух объектах; или бригада, у которой истёк допуск; или наряд, пересекающийся с другим по месту и времени.
- **Детерминизм**: `random.seed(42)`. Демо должно повторяться один в один.
- **Один вызов**: `python backend/seed.py` очищает и наполняет. Перезапуск безопасен.
- Идентификаторы и поля — английские; человекочитаемые значения — русские.

Запиши в `docs/DATA.md` три строки: что сгенерировано, где лежит «подсадной» случай, как пересоздать.

## Режим B — профиль (данные дали)

10 минут, не больше — иначе утонешь:

```
1. размер, формат, кодировка, разделитель
2. колонки: имя, тип, доля пустых, 3 примера значений, min/max для чисел и дат
3. ключи и связи между файлами, если их несколько
4. что в данных можно показать как «отклонение» для демо
```

Результат — `docs/DATA.md`: таблица колонок + один абзац «сценарий для демо» + команда загрузки. Если данные грязные — **не чистить всё**, вырезать чистое подмножество под сценарий и сказать об этом в README честно.

## Общее

- Загрузка данных — отдельный эндпоинт или скрипт, не ручная вставка в базу.
- Секреты и персональные данные из выданного датасета в README и видео не попадают.
