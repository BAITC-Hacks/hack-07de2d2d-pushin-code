Архитектура Windcast

Числа прогноза считает модель, порядок шагов и решения — агент. Ниже: где что работает, что внутри бэкенда, в каком порядке всё происходит и через какие запросы фронтенд говорит с бэкендом.

Где что работает

Пользователь приходит на pushin.codes. Caddy отдаёт страницы фронтенда, а всё, что начинается с /api/, передаёт бэкенду. Во внешние сервисы ходит только бэкенд.

Что внутри бэкенда

API запускает агента. На каждом шаге агент спрашивает OpenAI, какой инструмент вызвать следующим, и вызывает его. Каждый вызов сразу уходит событием на экран. Без ключа OpenAI агент идёт по тем же шагам по заданным правилам.

Когда что происходит

АЗаранее, один раз — Куба из командной строки

  1. входДанные турбин и архив погодыdata/raw/*.csvOpen-Meteo 06.2024 – 01.2026
  2. подготовкаЧасы, простои, дыры → флаг validhourly.parquet
  3. обучениеLightGBM: прогноз ветра → мощностьP10 · P50 · P90
  4. результатМодель лежит в репозиторииmodels/*.pkl

БПользователь нажимает «Выпустить прогноз на 05.02» — главный сценарий

Сплошная стрелка — запрос, пунктир — ответ. Шаги 6–12 повторяются, пока агент не опубликует прогноз. Каждый шаг появляется на экране сразу: SSE идёт через Caddy без буферизации.

Б′Кнопка «Имитировать новый прогон погоды» — пересчёт

  1. Экран шлёт тот же POST /api/runs на тот же день.
  2. Агент берёт свежий прогон погоды через fetch_weather и сравнивает его со старым.
  3. Ветер сдвинулся больше чем на 0,5 м/с или анализ поднял флаг — агент вызывает recalc_forecast, иначе оставляет v1 и объясняет почему.
  4. publish_forecast публикует v2 со строкой «что изменилось».
  5. На графике v2 сплошной линией, v1 пунктиром.

ВФевраль целиком — кнопка «Прогнать февраль» или CLI

  1. запускPOST /api/backtest илиpython -m windcast.backtest
  2. циклПуть Б для каждого выпуска31.01 → 28.02
  3. файлыПрогнозы и ленты шаговoutputs/forecasts/*.csvoutputs/traces/*.jsonl
  4. проверкаБез будущего, 48 ч × 3, P10 ≤ P50 ≤ P90scripts/verify.py → PASS

Где встречаются фронтенд и бэкенд

Сула и Куба договариваются только об этих запросах. Пока бэкенда нет, фронтенд работает на заглушках того же формата. Ошибки — 400 и 404 с текстом, не 500.

ЗапросКто и когда зовётЧто возвращает
GET /api/issuesЭкран при открытиидаты выпусков, версии, статусы
POST /api/runs«Выпустить прогноз», «Имитировать новый прогон»{run_id} — агент стартовал
GET /api/runs/{id}/eventsЭкран, сразу после run_idпоток шагов агента (SSE), последним — итог
GET /api/runs/{id}Экран, если поток оборвалсяпрогон целиком, со всеми шагами
GET /api/forecasts/{D}Экран, после итога48 ч × турбина 1, 2, ВЭС: P10 / P50 / P90, факт, флаги, сводка
GET /api/forecasts/{D}.csvКнопка «Скачать CSV»CSV выпуска
POST /api/backtest«Прогнать февраль»{id}, дальше те же события SSE
GET /api/metricsЭкран «Качество»ошибка модели и базовых методов на январе
