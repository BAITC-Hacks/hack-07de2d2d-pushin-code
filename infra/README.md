# Инфраструктура — подготовить ДО хакатона

Один хост, docker compose, Caddy с автоматическим TLS. Никаких вторых машин в рантайме.

## Один раз, до 23.09

1. **DNS**: A-запись поддомена (например `hack.<домен>`) → IP сервера. Проверить: `dig +short hack.<домен>`.
2. **Порты 80 и 443** открыты наружу.
3. На сервере: Docker + compose plugin. `docker compose version`.
4. Клонировать репозиторий в `/srv/hackalem` (на дне — заменить на выданный платформой: `git remote set-url origin …`).
5. `cp infra/.env.example .env` → вписать `DOMAIN` и `OPENAI_API_KEY`.
6. **Прогон на заглушке**: положить минимальные `backend/` (отдаёт `/health`) и `frontend/` (одна страница) с Dockerfile, запустить `infra/deploy.sh`. Должна открыться `https://hack.<домен>` с валидным сертификатом. Это проверка DNS, TLS и compose разом.
7. С ноутбука: `ssh <host> 'cd /srv/hackalem && infra/deploy.sh'` — работает без пароля (ключ).

## Требования к сервисам (для Кубы и Сулы)

- `backend/Dockerfile`, слушает `0.0.0.0:8000`, отдаёт `GET /health` → `{"ok": true}`. Читает `OPENAI_API_KEY` из окружения.
- `frontend/Dockerfile`, слушает `0.0.0.0:3000`, статика или dev-сервер — неважно. API зовёт по относительному пути `/api/...` — Caddy проксирует.
- SSE идёт через `/api/runs/{id}/events` — в Caddyfile уже `flush_interval -1`.

## На дне

`infra/deploy.sh` после каждого слияния в `main`. Первый деплой — в 0:30, заглушка. Не ждать «когда будет что показать».

## Если сервер недоступен с Wi-Fi площадки

Телефон как точка доступа → ssh через него. Заранее знать, чей телефон и что у него хватает трафика.
